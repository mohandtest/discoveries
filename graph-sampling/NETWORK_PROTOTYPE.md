# Prototype: triangle structure under a fixed-degree null

Given a simple, undirected, unweighted graph, `network_null.py` samples graphs that retain each node's exact degree and compares their triangle counts with the observed count. This can help explore whether triangle abundance is explained by degrees alone. It is an experimental research prototype, not a validated statistical service.

## Run

Requires Python 3, with no third-party libraries:

```sh
cd graph-sampling
python3 -m unittest discover -v
python3 network_null.py data/karate.edgelist --chains 8 --burn 20000 --samples 200 --thin 200 --csv my_samples.csv
```

Each input line contains two whitespace-separated node labels; an isolated vertex is represented by a single label. Comments start with `#`. Repeated edges and self-loops are errors. A CSV output path must not already exist. JSON is written to standard output; redirect it to save the run. Seed, attempted-step budgets and input SHA-256 are reported.

## Demonstration

The example is the unweighted projection of Zachary's karate club graph as published in [NetworkX's social graph source](https://networkx.org/documentation/stable/_modules/networkx/generators/social.html), based on Wayne W. Zachary, *An Information Flow Model for Conflict and Fission in Small Groups*, Journal of Anthropological Research 33, 452–473 (1977). The data represent a particular historic network, not a general claim about social networks. Node labels are those used by NetworkX and weights are discarded.

The observed graph has 34 vertices, 78 edges and 45 triangles. Three exploratory runs, each with 8 chains and 200 samples per chain, produced:

| Burn-in attempts | Attempts between samples | Mean null triangles | Fraction at least 45 |
| ---: | ---: | ---: | ---: |
| 5,000 | 50 | 39.413 | 0.112 |
| 20,000 | 200 | 39.442 | 0.123 |
| 80,000 | 800 | 39.414 | 0.124 |

These use seeds 20261110–20261117. The middle run's raw samples and JSON summary are in `results/karate_samples.csv` and `results/karate_summary.json`. The results provide no strong evidence of excess triangles at the customary 5% level under this particular null model. Similar results at longer budgets are reassuring but do not establish convergence, independent samples, or a calibrated hypothesis test.

## What the code does and does not establish

The kernel selects two distinct edges uniformly and one of two rewirings uniformly. Invalid proposals hold the current state; attempts include those holds. The proposal probability for each valid transition equals its reverse, giving the uniform distribution over fixed-degree labeled simple graphs as a stationary target. The implementation is a different kernel from the quadruple sampler in the exact audit. It is not a verified implementation of OpenAI/math #131.

The small six-vertex test checks that simulated triangle frequencies are near the exact 1/7 value. Tests also check degree and simple-graph invariants and basic input handling. These checks do not prove correctness for every graph or bound mixing time.

Chains start from the same observed graph with distinct seeds. The between-chain standard errors reflect variation among the chain estimates, but exclude initialization and mixing bias. A zero-hit tail estimate does not mean the tail probability is zero; it also gives no useful standard error here. Basic triangle R-hat is only a warning indicator and can look good even when all chains are stuck similarly. The full samples are correlated, and none of these diagnostics prove mixing.

The null does **not** preserve connectedness, weights, direction, time, groups, geography or other domain constraints. It may include disconnected graphs. It answers a conditional graph-structure question, not why ties formed, causality, or whether the data were generated by this model. Directed, bipartite and weighted data require different state spaces and kernels. Do not silently use this prototype on them.

For further work: validate multiple statistics and deliberately different starting states against exact small graphs; quantify false reassurance and Monte Carlo error; compare with a carefully matched independent implementation; test a second real dataset and domain-specific constraints before making practical or scientific claims.
